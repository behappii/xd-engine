# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Про проект

Софтверный (CPU) 3D-растеризатор на Rust. Пишется с нуля как **учебный проект**: цель владельца — разобраться в компьютерной 3D-графике и в Rust, поэтому внешние библиотеки для математики и рендеринга сознательно не используются. Из зависимостей только `winit` (окно и события) и `pixels` (пиксельный буфер поверх окна) — вся геометрия, матрицы, клиппинг и растеризация свои.

Отсюда следуют рабочие соглашения:

- **Комментарии и коммиты — на русском.** Держись этого стиля.
- Комментарии объясняют **почему** так, а не что делает строка: подводные камни, неочевидные решения, места, где легко ошибиться. Плотность высокая — это часть учебной ценности кода.
- Объяснять принцип важнее, чем быстро выдать работающий патч. Если решение неочевидно (перспективная коррекция, расщепление вершин, порядок обхода), стоит развернуть, что происходит и почему альтернатива хуже.
- Не тащить внешние крейты вместо того, что можно написать руками, — это лишает проект смысла.

## Команды

```bash
cargo run                  # запустить движок (окно)
cargo run --release        # то же, но с реальной производительностью
cargo build
cargo clippy --all-targets

cargo test                             # всё: юнит-тесты + tests/render.rs
cargo test --lib                       # только юнит-тесты внутри модулей
cargo test --test render               # только интеграционные
cargo test имя_теста                   # один тест по подстроке имени
cargo test имя -- --nocapture          # с выводом println!
```

Управление в окне: `WASD` — движение, `Space`/`LShift` — вверх/вниз, стрелки — поворот камеры, `Escape` — выход. FPS выводится в заголовок окна.

## Архитектура

`src/lib.rs` — библиотечный крейт `xd_engine`, где живёт весь движок. `src/main.rs` — обычный внешний потребитель: собирает демо-сцену и запускает цикл. Такое разделение сделано ради тестов: `Scene::draw` пишет в обычные буферы и окна не требует, поэтому кадр рендерится прямо в тесте.

Пайплайн одного кадра (`app.rs` → `scene.rs` → `renderer.rs`):

```
Mesh (Vertex: позиция + нормаль, локальные координаты)
  ↓ Instance::get_model_matrix   T · (Rx·Ry·Rz) · S
  ↓ Scene::draw — вершинный этап, один проход по вершинам:
      позиция → MVP → clip space (Vec4)
      нормаль → transform_dir → мир → яркость по Ламберту   (затенение по Гуро)
  ↓ is_backface — отсечение по знаковой площади в NDC
  ↓ ShadedVertex = clip-позиция + цвет (база грани × яркость вершины)
  ↓ clip_triangle_near — Сазерленд–Ходжман, режет позиции И атрибуты
  ↓ draw_triangle_filled — barycentric-растеризация с перспективной коррекцией
  ↓ DrawContext::set_pixel_depth — тест глубины по 1/w, запись в кадр
```

Модули: `math` (Vec3/Vec4/Mat4), `clipping`, `renderer` (пиксели и растеризация), `scene` (Mesh/Instance/Scene и сборка кадра), `app` (обработчик событий winit), `config` (константы), `fps_counter`.

## Инварианты, которые легко нарушить

Всё ниже — вещи, которые не видно из одного файла, а сломать можно одной строкой.

**Точка против направления.** `&Mat4 * Vec3` подставляет `w = 1.0` и прибавляет столбец трансляции — это для позиций. Для нормалей, осей и скоростей есть `Mat4::transform_dir` с `w = 0.0`. Здесь уже был баг: нормали умножались как точки, и освещение врало тем сильнее, чем дальше объект от начала координат. Регрессия закрыта тестами `transform_dir_ignores_translation` и `shading_does_not_depend_on_world_position`.

**Два типа вершины, не путать.** `scene::Vertex` — сырые атрибуты меша в локальных координатах. `renderer::ShadedVertex` — результат вершинного этапа: позиция в clip space плюс интерполируемые атрибуты. Разделение то же, что между входом вершинного шейдера и varying на GPU. Новый атрибут (UV, цвет вершины) надо заводить в обоих и протаскивать через `lerp_shaded`.

**Перспективная коррекция.** Барицентрики считаются на экране, уже после перспективного деления, а оно нелинейно. Поэтому в `draw_triangle_filled` интерполируются `attr/w` и `1/w` по отдельности, а в пикселе одно делится на другое. Любой новый интерполируемый атрибут обязан пройти через ту же схему — иначе он «поплывёт» на гранях под углом к камере.

**Клиппинг идёт ДО перспективного деления.** Поэтому в `lerp_shaded` обычный линейный lerp корректен: в clip space атрибут вдоль ребра линеен. Тот же lerp после деления был бы уже неверен.

**Depth-буфер хранит `1/w`, а не `z`.** Больше — значит ближе, `0.0` = бесконечно далеко (буфер так и очищается). `z` в экранном пространстве нелинеен, интерполировать его барицентрически нельзя; `1/w` — линеен.

**Порядок обхода.** Против часовой стрелки при взгляде снаружи. Тогда `cross(b - a, c - a)` смотрит наружу, а `is_backface` отбраковывает грани с площадью `<= 0`. Новую геометрию проверяй тестом «нормаль сонаправлена с центром грани» (см. `assert_normals_point_outward` в `scene.rs`).

**Плоское против гладкого затенения.** `Mesh::flat_shaded` расщепляет вершины: каждый треугольник получает свои три, потому что нормаль у грани своя (куб — 8 позиций → 36 вершин). `Mesh::smooth_shaded` вершины наоборот разделяет и усредняет нормали по сходящимся граням. Гуро виден только на гладких мешах — на `flat_shaded` все три яркости грани совпадают и интерполировать нечего. Если правишь позиции вершин руками, зови `recalculate_flat_normals`, иначе предвычисленные нормали устареют.

**Геометрически режется только ближняя плоскость.** Остальные пять решаются отсечением габаритного прямоугольника по экрану в `draw_triangle_filled`. Near-плоскость обязательна: без неё случится деление на `w <= 0`.

**Размер кадра — не константа.** `WIDTH`/`HEIGHT` в `config.rs` задают только стартовый размер окна, и то в логических пикселях. Действующий размер живёт в полях `EngineApp::frame_width/frame_height`, и от него зависят сразу три вещи: длина `depth_buffer`, индексация пикселей и `aspect` матрицы проекции. Все трое обновляются в одном методе `EngineApp::resize` — и создание окна, и `WindowEvent::Resized` идут через него, чтобы буферы не разъехались. Различай логические пиксели (то, чем мыслит ОС) и физические (`window.inner_size()`, на Retina вдвое больше по оси): поверхность вывода — всегда физические. Регрессия закрыта тестами `widening_the_viewport_adds_margins_instead_of_stretching` (горизонталь, ловит aspect) и `taller_viewport_scales_the_picture_with_it` (вертикаль, ловит зашитую высоту в переводе NDC в пиксели).

## Тестирование

39 тестов: юнит-тесты в `#[cfg(test)] mod tests` внутри модулей, интеграционные в `tests/render.rs` (видят движок только через публичный API).

Приёмы, которые тут уже работают и которые стоит продолжать:

- **Рендер в тесте без окна.** `Scene::draw` принимает срезы — кадр можно отрендерить и разглядывать пиксели (`tests/render.rs`).
- **Ожидание считается независимо от кода.** Тест перспективной коррекции подбирает геометрию так, что барицентрическая координата вычисляется прямо из `x` пикселя, и ожидаемый цвет выводится формулой на бумаге, а не повторением растеризатора. Совпадение побайтовое.
- **Проверять, что тест ловит баг.** После починки временно верни поломку и убедись, что тест краснеет. Зелёный тест, который не падает на сломанном коде, бесполезен.
- **Хеш кадра как проверка рефакторинга.** Отрендерить фиксированную сцену, взять хеш буфера до и после — если рефакторинг не должен был менять картинку, хеши обязаны совпасть. Так проверялись переход на `Vertex` и внедрение интерполяции.

## Известные пробелы

Не баги, которые нужно срочно чинить, а осознанное состояние — чтобы не «исправлять» это как регрессию и не открывать заново:

- **Верхней границы разрешения нет.** Буфер кадра следует за окном один в один, а растеризатор однопоточный и платит за каждый пиксель: развёрнутое на 5K окно — это ~15 млн пикселей на кадр. Разменивается на резкость через `RENDER_SCALE` в `config.rs`, автоматики нет и не планировалось.
- Backface-culling выполняется до near-клиппинга: треугольник, пересекающий камеру, всегда считается лицевым.
- Проволочный режим (`as_wireframe`) не тестирует и не пишет глубину — результат зависит от порядка инстансов.
- Залитые пиксели всегда пишут альфу 255: смешивания в пайплайне нет.
- Нет UV и текстур, нет `Mat4::inverse` (а значит и нормальной матрицы для неравномерного масштаба), нет отсечения по пирамиде видимости на уровне инстанса, растеризация однопоточная.
- `cargo clippy` даёт 7 предупреждений, все косметические (три `Default` для публичных типов, остальное — стиль).
